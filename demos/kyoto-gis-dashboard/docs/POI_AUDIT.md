# 景点数据核查、交叉验证与整合（POI Data Audit）

2026-11-15 · 范围：Dashboard 原有的 523 个景点记录，对照 `DSIGHT_1.csv`、OpenStreetMap 和 Wikidata。

逐条结果见 **`data/audit/poi_audit_checklist.csv`**（809 行）：每条变动或检查过的 POI 都列出了原始 ID、匹配对象、处理方式、位置依据和最终结果。机器可读的完整结果在 `data/audit/poi_audit.json`。

## 2. CSV 与 Dashboard 的对应关系

- CSV 归并为 **141 个地点**。
- **已在 Dashboard 上**：1 个，伏见稻荷大社（A00306），CSV 的 3 条记录挂在它下面。
- **Dashboard 记录属于某个 CSV 地点的一部分**：二条城的 4 个观景点（A00078、A00487、A00488、A00490）、高台寺掌美术馆（A00077）、豊国神社宝物館（A00065）。它们保留原样，记录上加了 `Part of` 父级关系。
- **只是同名、没有证据是同一地点**：CSV「地蔵院」和 Dashboard A00150「地蔵院」。京都有好几座地蔵院，**没有关联**，在清单里标为 "same name only (not confirmed)"。

## 3. 定位规则（CSV 没有坐标，不生成坐标）

一个 CSV 地点只有同时满足以下条件，位置才算"已核实"：

1. 在京都府内的 OSM 寺社、史迹或景点中，有**完全同名**（或别名、正式名）的地点。名称不同时（例如 CSV 写「永観堂」），会先找日文名一致的 Wikidata 条目，再找标了这个条目的 OSM 地点。
2. CSV 有地址时，这个 OSM 地点必须位于地址所写的区或市（用 N03 多边形判断）。
3. **第二个独立来源**确认：OSM 地点上标注的 Wikidata 条目，或日文名一致的 Wikidata 条目，坐标与 OSM 位置相距 600 m 以内。
4. 同名地点不止一处、又没有地址可以区分时，一律标为 **Unverified Location**。大寺院的院区多边形与院内的同名标识牌、景点点位（同一区、1.2 km 内，且标的是同一个 Wikidata 条目，或者另一个不是寺社本身）视为同一处。

结果：**77 个已核实**（61 个用寺社院区多边形的中心，16 个用 OSM 点），**63 个未核实**：

| 原因 | 数量 | 例子 |
|---|---|---|
| OSM 里找不到这个名称 | 36 | 永観堂、新日吉神宮、几座古坟 |
| 同名地点不止一处，无法区分 | 12 | 白山神社（5 个市町）、今宮神社、醍醐寺、本願寺、地蔵院 |
| 只有 OSM 一个来源 | 9 | 金地院、御香宮 |
| OSM 同名地点不在地址所写的区 | 6 | 曼殊院、清浄華院 |

未核实的地点**没有加到地图上**，只保留在清单里。

## 4. 重复检测（原有 523 条）

自动检测（相距 ≤ 500 m，名称相同或一个包含另一个，或标了同一个 Wikidata 条目，或坐标完全相同）提出了 44 对。每一对都对照 OSM 的标签、编辑日期和编辑者做了人工复核，结论写在 `data/audit/poi_decisions.json`：

| 类别 | 记录 | 处理 |
|---|---|---|
| **A 确定重复** | 绘马展示资料馆 A00296 → A00297；Best Breakfast Point A00223、A00224、A00225 → A00222；黄桜記念館 A00459 → A00076 | 在地图图层中合并，原记录仍保留在 `data/raw`。被合并记录的编号仍然能搜到保留下来的那一条。 |
| B 疑似重复 | おもかる石（A00085 / A00360，现场是一对）、石塀小路（两点相距 134 m）、保津峡展望台（相距 341 m） | 都保留，卡片上标注"需要确认" |
| C 相关 POI | 股のぞき台（傘松公園 4 个、ビューランド 7 个，现场确实是多个台子）、宇治橋和三の間、京都御所和入口 | 都保留，标注为同一组 |
| D 不同地点 | 二条城的两个观景点（A00078 的日文名疑似从 A00488 复制，已标注但没有改名）、SAMURAI NINJA MUSEUM 的两个门店 | 都保留 |

自动检测里有 29 对被判为 A，其中大部分是股のぞき台。复核后只有上面 3 组、5 条记录确实是重复。

## 5. 坐标检查（原有 523 条）

- 坐标都有效，都在 N03 京都府的行政区多边形内；没有两个记录共用同一个坐标。
- 2026-11-15 按 OSM 编号重新读取了 523 个节点：**全部还在原位置（30 m 内），名称也没变**。
- 这批记录的位置只有 OSM 一个来源，卡片的 Technical Details 里写明"One source: not independently confirmed"。只有新增的地点写的是两个来源的核实依据。
- 没有检查坐标是否落在道路或河流上（项目里没有水系的面数据）。步行分析里每个点到最近道路的距离单独列出，可以作为参考。

## 6. 整合到 Dashboard

- 流程：`scripts/fetch_osm_reference.py`（OSM 参考地点，需要联网）→ `scripts/audit_poi.py`（只读核查）→ 人工复核写入 `data/audit/poi_decisions.json` → `scripts/poi_reconcile.py`（生成地图图层）。`scripts/prepare_data.py` 现在也调用同一个函数，不再原样复制 523 条。
- 地图图层：**595 条** = 523 − 5（合并）+ 77（新增）。类别：attraction 231、viewpoint 243、museum 101、castle 20。
- 新增地点的编号 A00524–A00600（`data/audit/poi_ids.json`，第一次生成后固定不变）。名称用 OSM 的日文名，CSV 的写法作为别名；英文名来自 OSM 的 name:en 或 Wikidata 标签。每条记录都带有 `wikidata`、`dsight_ids`、`location_evidence` 和 `point_is`。
- 搜索：日文名、英文名、别名都能搜到；英文不区分连字符、空格和音调符号（`Nanzen-ji`、`nanzenji`、`NANZEN JI` 都能找到南禅寺）。
- 详情卡片：新增 `Part of`、`At this site`（CSV 中这个地点的建筑、文物和名木，它们没有自己的坐标点）、`Merged`、`Group`、`Check`（疑似重复）、`Note`；Technical Details 里显示位置核实依据、Wikidata 和 DSIGHT 编号。
- 跟着重新生成的派生数据：行政区关联、英文名、地点上下文、核密度（改为基于地图图层）、步行路线（595 个点全部重新计算）。新地点没有巴士线路关联，因为巴士数据包只关联到原有记录。
- 照片：新地点用了核实位置时所用 Wikidata 条目的照片，75 张逐张人工看过（照片从 68 张增加到 143 张）。

## 7. 没有做的事和限制

- 63 个未核实的 CSV 地点没有加到地图上，CSV 的建筑、文物和名木也没有单独的坐标点（只列在所属地点下）。
- 原有 523 条的坐标没有找到第二个独立来源；B 类疑似重复需要实地或进一步资料确认。
- `DSIGHT_1.csv` 的来源和许可证不明，所以**原始文件没有提交到仓库**（放在 `data/raw/dsight/`，已在 .gitignore 中排除）。界面也没有显示它的说明文字，只用了名称、编号和地址这类事实信息。
